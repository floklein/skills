# Viral TikTok Creator

Create one focused TikTok that can stop the scroll, hold attention, and give a specific viewer a reason to transmit it. Treat virality as uncertain. Optimize the creative and learning loop the creator can control.

## Route the task

- For a new video or rewrite, run the full process.
- For hook, format, or series variants, read [references/patterns.md](references/patterns.md), then run the process from the relevant step.
- For a critique, audit the supplied material, name the highest-leverage weakness, and provide a revised version unless the user requests analysis only.
- For analytics or iteration, read [references/optimization.md](references/optimization.md), diagnose the earliest meaningful signal, and propose one controlled next test.

## Process

### 1. Distill the transmission

- Infer one target viewer and one premise from the request and available context.
- Choose the primary viewer response: share, save, comment, or rewatch.
- State who would transmit the video to whom and why. If there is no credible answer, sharpen the premise before scripting.
- Identify the proof, example, demonstration, transformation, or opinion that will earn the payoff.
- Preserve the user's voice, facts, and intended meaning. Use an explicit placeholder for an indispensable missing detail.

Complete this step when one viewer, one premise, one proof mechanism, and one reason to transmit are identifiable.

### 2. Find the opening

- Draft ten materially different opening combinations of first visual and first line. Keep this legwork internal unless the user requests variants.
- Select the opening that creates the strongest truthful curiosity, recognition, utility, surprise, or tension.
- Start at the result, action, conflict, or sharp claim. Make the first frame understandable without prior context.
- Land the hook within the first two seconds and make the value promise clear by roughly five seconds.
- Ensure the hook sets up the actual payoff rather than exaggerating it.

Complete this step when the opening works with sound off, the spoken line adds value, and both lead naturally to the same payoff.

### 3. Build the hold

- Use **hook -> promise -> delivery -> payoff -> close** as the default spine.
- Cover one useful or entertaining idea. Use short spoken sentences and concrete examples.
- Make every beat add information, evidence, anticipation, or emotional movement.
- Assign visual changes only when they clarify the story, prove the claim, increase anticipation, or reset attention.
- Deliver a payoff more specific than the hook implies.
- End immediately after the payoff or attach one natural call to action that matches the intended response.

Complete this step when every sentence and shot advances the same promise, and removing another beat would cost clarity, proof, tension, or payoff.

### 4. Make it recordable

- Turn the script into spoken words, on-screen text, and a shot or evidence plan.
- Design for vertical 9:16 viewing, readable captions, clear footage, and interface-safe text placement.
- Prefer human delivery, voiceover, dialogue, music, or sound effects that serve the idea.
- For a search-led video, read the search-intent section in [references/optimization.md](references/optimization.md) and apply it to the script and packaging.
- Use a few precise hashtags only when they add discovery context.

Complete this step when all dialogue, shots, evidence, and on-screen text needed to record and edit the video are specified.

### 5. Audit the result

Check every draft against all three gates:

- **Stop:** The first frame is legible without context, something interesting happens immediately, and the hook truthfully promises the payoff.
- **Hold:** Every beat earns its duration, visual changes have a job, and the payoff is concrete rather than generic.
- **Transmit:** A named viewer has a credible reason to share, save, comment, or rewatch.

Also check factual support, spoken naturalness, caption readability, platform-safe framing, requested constraints, and whether the ending preserves the strongest moment. Revise until every gate passes.

## Learn from performance

When analytics are available:

1. Locate the earliest meaningful drop, plateau, or replay spike.
2. Tie it to the exact line, shot, transition, or promise at that moment.
3. Form one causal hypothesis.
4. Preserve the parts already supported by the data.
5. Change one major variable in the next version.

Complete the diagnosis when the next version tests one explicit hypothesis and differs on one named variable. Use the video's own baseline rather than an unofficial universal completion threshold.

## Deliver the result

- For a creation request, lead with the final script. Include timestamps, spoken lines, on-screen text, and shots when the user needs a production-ready plan.
- Give three selected hook variants when variants are requested or when the opening is the main uncertainty.
- For a critique, give a concise stop, hold, transmit diagnosis, then the rewrite.
- For analytics, give the observed signal, likely cause, next test, controlled variable, and revised opening or script.
- Keep rationale brief unless the user asks for strategy.
- Describe the result as more retention-led or transmissible while treating viral reach as unpredictable.

Verify current TikTok features, specifications, discovery tools, recommendation factors, and performance programs before presenting them as facts.
