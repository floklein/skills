# Viral Tweet Writer

Build every post around one sharp idea, expressed with maximum clarity and tension. Treat virality as uncertain. Optimize the parts the writer can control: readability, reply value, bookmark value, and repost value.

## Process

### 1. Distill the payload

- Infer the target reader and the post's purpose from the request and available context.
- Reduce the material to one claim that can be understood without an introduction.
- Identify one truthful proof point, example, number, contrast, or observation that makes the claim credible.
- Preserve the user's intended meaning and recognizable voice when rewriting.
- Use facts, results, and first-person experiences supplied by the user or verified from sources. Use a clear placeholder when an indispensable detail is missing.
- Ask a question only when the missing context would materially change the claim. Otherwise, make the smallest reasonable assumption.

Complete this step when one audience, one claim, and one concrete support point are identifiable.

### 2. Shape the post

- Use **claim -> proof -> payoff** as the default spine.
- Start with the interesting part. Create curiosity, tension, utility, recognition, or surprise in the opening line.
- Choose one structure that serves the claim. When the structure is unclear or the user requests variants, read [references/patterns.md](references/patterns.md) and select genuinely different angles.
- Recommend an image, screenshot, GIF, or video when the evidence is easier to understand visually. Write the text to set up that demonstration.

Complete this step when the opening is interesting on its own and every later beat supports the same claim.

### 3. Draft

- Write in the user's language and voice unless requested otherwise.
- Use short sentences, concrete nouns, active verbs, natural spoken language, and deliberate line breaks.
- Place the specific evidence or observation immediately after the claim.
- End on the most memorable implication, lesson, or contrast.
- Default to one standalone post. Expand into a thread only when the user requests one.

Complete this step when every sentence contributes claim, proof, or payoff.

### 4. Compress

- Remove setup-only openings, repeated explanations, soft hedges, and empty corporate phrasing.
- Keep qualifications that prevent the post from becoming misleading.
- Prefer the shortest complete version. Respect any requested character limit and favor a compact single post when no limit is given.
- Default to zero hashtags. Use at most two only when they provide known discovery value.
- Use emojis and calls to action only when they match the user's voice and the post's purpose.

Complete this step when removing another line would cost meaning, credibility, or rhythm.

### 5. Audit and revise

Check every draft against all of these criteria:

- **Singularity:** It makes one claim.
- **Hook:** The first line begins with the interesting part.
- **Credibility:** Every fact, number, result, and personal experience is supplied or verified.
- **Clarity:** A target reader can understand it on the first pass.
- **Repost value:** Sharing it helps the reader express a belief, teach something, signal taste, or create an emotion.
- **Voice:** It preserves the user's recognizable phrasing, cadence, and level of formality.
- **Density:** Every sentence earns its place.
- **Constraint:** It satisfies the requested format, length, language, and number of variants.

Revise until every criterion passes. Use this final test: **What does reposting this say about the person reposting it?**

## Deliver the result

- For a drafting request, lead with one complete post and omit rationale unless requested.
- For variants, label each by its distinct angle and make each one publication-ready.
- For a critique, give a concise diagnosis using claim, hook, proof, payoff, and voice, then provide a rewrite unless the user requested analysis only.
- Put any necessary factual caveat after the post so the draft remains easy to copy.
- Describe the result as sharper or more repostable while treating virality as unpredictable.

When the user asks about posting time, engagement tactics, measurement, or reusing a strong idea, read [references/publishing.md](references/publishing.md).
